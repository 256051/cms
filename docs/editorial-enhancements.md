# 内容运营功能完善

本次保持 Admin / Editor 的现有发布权限，审批流和图片压缩未加入。沿用 FreeSql、单站点、单 API 实例及四数据库支持。这些功能从 schema 9 引入；当前进一步升级至 schema 14，见 [第二轮完善](next-enhancements.md)，部署前需备份数据库、附件、密钥和部署配置。

## 编辑与恢复

- 停止输入 5 秒自动保存草稿；手动保存和 Ctrl/Cmd+S 继续有效。未填写标题时先保存本机副本。保存期间暂时禁用输入，防止保存响应覆盖编辑。
- 本机副本按账号、类型、文章隔离，重新打开可选择恢复或放弃；成功保存后清除副本。浏览器存储不可用或空间不足会明确提示。
- 失败保留输入，最多自动重试两次；此后提示手动重试。版本冲突暂停自动保存，可将输入另存为新草稿，不自动覆盖他人的版本。
- 显示最后保存时间。草稿保存成功但发布失败时，已保存草稿仍在服务器。

## 历史版本与回收站

- 保存、发布、下架、恢复、批量操作记录历史。历史列表可只读查看、恢复为当前草稿；当前公开内容保持原样，需重新发布才更新。
- 旧文章在升级后首次修改前补存原草稿和原发布快照；升级前已覆盖的版本无法找回。
- 删除改为移入回收站，立即停止公开并取消发布计划；保留评论、历史与附件引用。回收站恢复后为草稿。
- 永久删除只允许回收站内容，校验版本并原子删除文章、评论和历史。有菜单引用时仍需先处理导航。
- 历史不自动清理；历史引用的附件、分类、标签仍受保护。附件引用列表能定位到文章或回收站。

## 发布与列表

- 支持定时发布、下架，输入使用浏览器本地时间，服务器存 UTC；清空对应时间并保存可取消。
- 发布计划固定采用设置时的已保存草稿；后续编辑需重新保存发布计划才能改变将要公开的内容。
- API 每 30 秒检查计划，重启后补执行。若发布和下架时间均已过，只执行下架。人工下架、批量下架均取消计划。
- `PublishedAt` 为首次发布时间，`LastPublishedAt` 为最近公开更新时间；旧文章重新发布不再置顶。历史数据的首次时间只能沿用升级前保存的发布时间。
- 列表支持草稿、已发布、回收站、分类、标签和关键词筛选；支持复制、批量修改草稿分类、批量下架。每批最多 100 条，所有成员校验通过后一次提交，冲突整批不写入。

## 咨询、附件与搜索

- 咨询可分配负责人、设置下次联系时间、筛选逾期项；后台显示逾期数。已完成和无效咨询不提醒。
- 跟进记录逐次追加，包含操作者、状态、备注、负责人和下次联系时间；旧备注首次更新时存入历史。
- CSV 导出当前筛选的全部咨询，含 UTF-8 标记和公式转义；咨询、跟进、导出仍仅管理员可见。
- 附件支持文件名搜索、类型筛选，引用位置覆盖草稿、发布、计划、历史、回收站和站点图片。
- 搜索包含已发布正文的纯文本，提供关键词附近摘要；草稿与历史不进入公开搜索。文章提供上一篇、下一篇、同分类相关文章。
- `/rss.xml` 提供最近 50 篇已发布文章摘要，页脚和元数据提供订阅入口；站点地图使用最近公开更新时间。

## 备份与明细维护

“备份与维护”提供立即备份、成功时间、失败状态和下载。ZIP 包含数据库逻辑数据、引用附件、认证密钥及逐文件 SHA-256 清单。备份共享现有串行写入事务，完成后原子更名；未完成文件不标记成功。

配置支持 appsettings、Consul KV 和环境变量，环境变量优先，修改后重启：

```json
{
  "Maintenance": {
    "BackupPath": "/data/backups",
    "BackupIntervalHours": 24,
    "TrafficRetentionDays": 180
  }
}
```

- 定时备份默认每 24 小时执行；访问明细自动清理仍默认 0（关闭），启用后保留 90–3650 天。
- 环境变量：`Maintenance__BackupPath`、`Maintenance__BackupIntervalHours`、`Maintenance__TrafficRetentionDays`。容器默认备份在持久化卷 `/data/backups`。
- 备份默认保留最多 14 份、最近 30 天；仅在新备份成功后清理，始终保留最新成功备份。份数／天数设为 0 可关闭对应限制，请安排受限的异地复制。通知和清理的当前能力见 [运营功能完善](operations-enhancements.md)。
- 清理删除期限前的访问与点击明细，清空长期未访问浏览器的最后 IP / 地区。保留站点累计浏览量、累计浏览器数、文章累计阅读与独立浏览器数；咨询和跟进不随明细清理。
- 期限前的日趋势、来源、设备、停留时长、深度和访问轨迹不保留。统计接口拒绝跨越清理起点的查询，不用零值冒充历史；维护页面显示实际明细起点。
- 逻辑备份逐表读取，适合当前单实例 CMS；大量明细站点仍可使用 [原生数据库备份](operations.md)。部署配置和应用镜像需另行保存，连接串与 Consul 凭据不写入下载包。

### 恢复到全新环境

停止恢复实例，配置空数据库、全新的附件与密钥目录，再执行：

```powershell
dotnet Cms.Api.dll --restore=D:\backups\cms-snapshot.zip
```

接收 schema 9–14 的完整备份，先检查清单、路径、哈希和附件字节。拒绝非空数据库和非空目录，不提供在线覆盖恢复；失败回滚数据库并清理本次创建的文件。恢复后核对登录、站点、附件、历史和咨询；旧令牌及发布计划也会恢复，正式启动前应核对。
