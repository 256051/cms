# 后台登录保护

进入 `/admin/login` 后，填写账号、密码和图片中的 6 位数字。图片支持“换一张”，刷新图片保留账号与密码。验证码加载失败时禁止登录，可点击“换一张”重试。密码管理器仍可填充账号和密码，手机显示数字键盘，输入验证码后可按 Enter 登录。

## 当前规则

- 同一客户端 IP：登录接口每分钟窗口最多 10 次，验证码接口最多 30 次，使用滑动窗口限流；超出返回 `429 / RATE_LIMITED` 和 `Retry-After`。
- 验证码：服务端使用安全随机数生成，3 分钟有效，绑定 `HttpOnly / SameSite=Strict` 浏览器 Cookie，HTTPS 部署同时使用 `Secure`；图片和接口禁止缓存。接口返回图片，不返回答案字段。刷新使同一浏览器的旧图失效；正确或错误回答均消费本次挑战，不能重复提交，也不能复制到另一浏览器使用。
- 账号：通过验证码后才计入密码尝试。15 分钟内连续 5 次失败后限制登录 15 分钟，成功登录清除计数。账号按去除首尾空格并转为小写后计数，不同 IP 共用该账号的限制；并发请求先预占尝试次数，最多放行 5 次密码验证。限制期间继续尝试不会延长等待时间，返回 `429 / LOGIN_LOCKED` 与剩余等待秒数。
- 登录失败：账号、密码输入保留，自动更换验证码；频率限制后显示等待时间并临时禁用提交按钮。服务端仍执行全部校验，刷新页面不能绕过账号限制。
- 保留 Cookie 会话认证、密码哈希、登录 CSRF 校验和统一的“账号或密码错误”提示，不暴露账号是否存在或停用。

## 接口变化

新增 `GET /api/v1/auth/captcha`，响应 `CaptchaView`：`id`、`image`（SVG data URL）、`expiresInSeconds`。登录 `POST /api/v1/auth/login` 现在必须提交 `username`、`password`、`captchaId`、`captchaCode`，同时携带挑战 Cookie 和 `X-CSRF-TOKEN`。已更新 OpenAPI 及生成的 TypeScript 契约；旧的仅账号密码登录调用需要适配。

## 部署边界

无需数据库升级、外部验证码账号或新配置项，兼容当前单 API 实例部署。计数和验证码使用容量有限的进程内缓存，缓存满时拒绝新尝试，不放弃校验；API 重启会清除计数并使旧验证码失效。多 API 实例部署前，需要将挑战消费与账号计数改成共享存储中的原子操作，例如 Redis。

IP 限流依赖真实客户端地址。现有 Compose 由 Nginx 覆盖转发地址头，API 仅信任配置中的代理网络；正式环境保持 API 端口不直接对外开放。不要把所有网络配置为可信代理。

内置图形验证码用于阻挡简单脚本，不能保证抵御图像识别或有针对性的自动化；账号/IP 限流是必要的共同保护。面向高风险公共入口时可进一步接入专业验证码和 MFA。测试中的字体解码仅存在于测试工具，不增加生产验证码绕过开关、答案接口或答案日志。

## 验证入口

- `dotnet tests/Cms.Checks/bin/Debug/net10.0/Cms.Checks.dll --login-protection`：可控时钟下验证过期、等待恢复、成功清零、并发账号尝试和验证码重放。
- `python tests/login_security.py`：自动创建独立 SQLite 站点，验证 Cookie/CSRF、错误统一、跨浏览器复制、跨 IP 账号限制、接口限流及并发重放；不连接本地预览数据库。
- `python tests/docker_smoke.py`：独立 Docker HTTPS 站点，执行包含登录页的全部浏览器回归；需要先构建两个镜像。登录页覆盖刷新、错误提示、失败保留输入、等待恢复、375/1440 像素布局和键盘提交。
