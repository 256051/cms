# 页面搭建与业务工具

本轮新增页面搭建体验、公共区块、通知、SEO 与地址管理、附件整理，以及产品／案例和咨询表单。继续使用现有管理员／编辑发布权限、单站点和单 API 实例。图片自动压缩和发布审核流程按此前决定暂缓。

## 页面搭建与公共区块

在独立页面、产品、案例或模板中使用页面搭建器。模块编辑支持本次打开期间最近 30 步撤销／重做；快捷键为 Ctrl/Cmd+Z、Ctrl/Cmd+Y，输入框内保留原生文本撤销。刷新后的恢复使用自动保存及历史版本。

模块正文可使用富文本，并为手机设置独立的对齐、间距、列数、字号和显示状态；手机样式在宽度不超过 600px 时生效。桌面／手机草稿预览使用当前站点主题、真实导航和页脚，预览中的链接和表单不会导航或提交。

后台“公共区块”用于维护多个页面复用的内容。保存草稿不会改变已发布页面；发布区块后，同步引用它的公开页面会使用新版本。区块支持历史版本恢复、回收站和定时发布。

- **独立复制**：把区块已发布的内容复制到页面，此后各自编辑。
- **同步引用**：公开页面读取区块的已发布版本；可“转为独立模块”后单独修改。
- 区块本身不能同步引用其他区块，避免循环。展开后每页最多 40 个模块、一个咨询模块；超出限制会拒绝发布。
- 已被公开页面或定时发布计划引用的区块不能下架或删除；永久删除还会检查草稿、历史版本和回收站引用。区块没有独立公开网址。
- 附件保护包括区块草稿、发布快照及历史版本。只有被公开页面实际引用的区块附件才公开，单独发布区块不会公开其全部附件。

## SEO 与访问地址

内容编辑页可填写独立 SEO 标题（最多 200 字）、描述（500 字）、分享图片和禁止收录设置。留空时使用现有标题、摘要及图片默认值；分享图片也使用附件预览选择窗口。禁止收录的页面设置 noindex，并从 sitemap 排除，仍可通过链接访问。

访问地址现在可以编辑：保存草稿时线上地址保持原样，发布后才切换；旧地址永久跳转到最新已发布地址。所有旧链接直接指向当前地址，多次改名不产生逐级跳转；改回自己曾用过的地址也可正常工作。

地址在文章、页面、产品、案例等内容之间保持全局唯一；草稿、回收站、旧链接和定时发布快照占用的地址不能被其他内容抢占。恢复历史内容时保留当前草稿地址，可另行修改后发布。下架后旧地址不再公开；永久删除内容会清理它保留的旧链接。

## 附件整理与裁剪

后台“附件”支持一次最多选择 50 个文件，逐个上传并显示结果；部分失败时保留失败文件，可单独重试。每个文件仍受原有类型和大小限制。

通过“名称与分组”编辑显示名称及分组，不移动或修改文件字节；保留原扩展名。列表和所有附件选择窗口均支持分组筛选，并与文件名搜索、类型筛选、分页配合。上传到选定分组后新文件继承该分组。

图片可按原比例、1:1、4:3、16:9 或 3:4 裁剪，通过主体左右／上下位置和放大控制保留区域。预览确认后另存为新的 PNG 附件，继承原分组；原图及已有引用不变，需在内容中选择新图并发布才会替换。GIF 裁剪为静态图片，输出最多 1600 万像素；不包含自动压缩或原文件覆盖。

## 产品、案例与咨询表单

后台新增“产品”和“案例”，复用草稿、发布、历史、回收站、封面和页面搭建。产品默认包含型号、参数、适用场景，案例默认包含行业、客户名称、实施成果；可改名、删除和新增业务字段。每份内容最多 20 个字段，名称 60 字、值 2000 字，均为纯文本。

业务字段随发布快照公开，草稿修改不会提前上线；历史恢复和复制保留字段，公开搜索包含字段名称和值。公开列表为 `/products`、`/cases`，详情为 `/products/{slug}`、`/cases/{slug}`。导航菜单可选产品／案例，搭建器“内容列表”模块可指定文章、产品或案例。

管理员在“咨询表单”配置附加字段。默认有意向产品、预算范围和预约日期；最多 20 项，可排序、设置必填，支持单行文本、多行文本、数字、日期、下拉选择（最多 20 个选项）。固定称呼、联系方式、需求描述和联系授权保持原有规则。

公开表单加载当前定义并校验必填、类型和选项。若管理员在访客填写期间改动了定义，提交失败仍保留当前输入，可更新表单字段后重试。咨询记录保存提交时的字段名称和值，后续改名或删除表单字段不会改写历史咨询；后台详情和 CSV 包含这些字段。咨询详情和联系方式仍仅管理员可见。

## 主动通知配置

支持新咨询、跟进到期、备份失败、定时发布／下架失败四类通知。默认关闭，可分别启用邮件和企业微信群机器人。后台“通知记录”展示渠道、状态、发送次数、下次重试时间和结果；管理员可手动重试失败记录。后台不显示 SMTP 密码或 Webhook 凭据。

配置放入现有 Consul JSON 的 `Notifications` 节点，或通过 API 容器环境变量设置；环境变量优先，修改后重启 API。示例值均须替换，不是可用凭据：

```json
{
  "Notifications": {
    "Enabled": true,
    "SiteUrl": "https://cms.example.com",
    "Email": {
      "Enabled": true,
      "Host": "smtp.example.com",
      "Port": 587,
      "EnableSsl": true,
      "From": "cms@example.com",
      "To": "operator@example.com",
      "Username": "cms@example.com",
      "Password": "REPLACE_WITH_SMTP_SECRET"
    },
    "WeCom": {
      "Enabled": false,
      "WebhookUrl": ""
    }
  }
}
```

环境变量对应 `Notifications__Enabled`、`Notifications__SiteUrl`、`Notifications__Email__Host` 等。`SiteUrl` 应与前台公开域名一致；密钥仅放部署环境或受控 Consul 配置，不提交仓库。

邮件使用 STARTTLS（常用端口 587），不支持要求连接时立即启用 TLS 的 465 模式。`To` 为固定运营收件人，最多 20 个、逗号分隔；成员填写通知邮箱后，咨询邮件优先发送给当前负责人；其他事件仍使用站点收件人，见 [运营功能完善](operations-enhancements.md)。企业微信启用时将群机器人完整地址填入 `Notifications:WeCom:WebhookUrl`，只接受 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?...`；本机 HTTP 地址仅用于隔离测试。

通知处理独立于定时发布任务，每 30 秒检查一次，每批最多 10 条；单次发送最多等待 15 秒，每轮最多尝试 5 次，失败后间隔约 2、4、8、16 分钟重试。手动重试开启新一轮额度，总尝试次数保留。停用渠道的待发消息保留但不阻塞已启用渠道。

同一事件与渠道有唯一记录，已成功事件不会因定时检查重复入队。首次启用跳过启用前的新咨询提醒，但会处理仍逾期的咨询和当前备份失败；已完成跟进、已恢复的备份或取消的发布计划对应待发提醒会取消。首次启用时间写入数据库，之后短暂停用再启用不会重置起点。

发送成功后才落库；若接收方已收到而进程崩溃或响应超时，重试可能重复到达，不能保证外部消息恰好一次。每条消息带事件编号方便识别；消息只包含事件说明和后台链接，不包含客户姓名、联系方式或需求内容。本轮只验证本地模拟邮件／HTTP 接收端，正式凭据与真实投递需在部署环境验证。

## 升级、备份与验收

当前 schema 为 **14**。已有数据库正常启动时按编号升级后才就绪；Docker 更新 API 使用同一启动流程。11 增加通知记录，12 增加 SEO 与旧地址，13 增加附件分组／版本，14 增加产品和咨询字段。首次空库仍需 `--initialize`，版本高于程序、版本记录缺失或升级失败时停止启动，避免带错版本运行。

逻辑备份包含新增字段和表，可将 schema 9–14 的归档恢复到独立空库，旧归档缺少的新表／字段使用默认值；附件、密钥和校验规则沿用 [备份恢复说明](operations.md)。升级前备份，降级程序不能直接连接已经升级的数据库。

验收脚本使用隔离数据库、随机端口和有独立名称的临时数据库容器，不使用日常站点；浏览器运行生产前端构建。本轮没有部署到正式环境或发送真实通知。

```powershell
dotnet build -c Release --no-restore
python tests/next_enhancements_browser.py
python tests/business_acceptance.py all
python tests/shared_blocks_acceptance.py all
python tests/seo_acceptance.py all
python tests/notification_acceptance.py all
python tests/editorial_acceptance.py all
python tests/startup_upgrade.py
$env:CMS_TEST_CONFIGURATION = 'Release'
python tests/run_matrix.py Sqlite
```

四库指 SQLite、PostgreSQL、MySQL 和 SQL Server；测试结果保存在各次运行的 `artifacts/<run>/`。最终验收记录见下方。
