# 运营功能完善（2026-09-23）

本次补齐备份管理、文章内容包、评论回复与批量审核、管理员恢复、通知测试、操作记录筛选和咨询专员。继续使用单站点、单 API 实例、FreeSql 和既有统一响应；没有新增 NuGet 或 npm 依赖。

## 备份文件与容量

后台「备份与维护」列出备份时间、文件名、大小、最新成功标记，可分别下载历史备份，显示备份所在磁盘的可用和总容量。磁盘不足或容量读取失败会在后台概览提醒。下载接口仅接受本应用生成的备份文件名，拒绝路径穿越和文件符号链接。

新增配置沿用 appsettings、Consul 和环境变量，修改后重启：

```json
{
  "Maintenance": {
    "BackupIntervalHours": 24,
    "BackupKeepCount": 14,
    "BackupRetentionDays": 30,
    "LowDiskSpaceMb": 1024
  }
}
```

对应环境变量为 `Maintenance__BackupIntervalHours`、`Maintenance__BackupKeepCount`、`Maintenance__BackupRetentionDays`、`Maintenance__LowDiskSpaceMb`。配置文件和缺项时的读取默认值均为 **24 小时、14 份、30 天、1024 MB**。显式设置备份间隔为 0 可关闭定时备份；份数或天数为 0 则关闭对应保留限制。启用两个保留限制时，超过任一限制的旧备份都会被清理。Consul 和环境变量仍可覆盖这些值。

只有新备份成功后才执行清理，始终保留最新成功备份；备份失败保留原有归档，清理失败显示单独提示并保留最新备份成功时间。并行发起备份会返回正在执行提示。请继续安排受限的异地复制；恢复仍只允许空数据库和空附件、密钥目录。

为保持数据库与附件快照一致，备份仍使用现有单实例写锁。大站点应在低峰备份或使用原生数据库备份，不以后台线程代替一致性保证。本次功能测试不代表生产容量或高并发基准。

## 文章导入导出

「文章」列表新增与产品、案例、独立页面相同的导入和导出按钮。可导出勾选项或完整筛选结果，包含最新草稿、分类标签、封面、正文附件和 SEO；导入统一创建新草稿，重映射附件与包内文章链接，重复地址自动改名。

仍限制每包 100 条、压缩后 50 MB、解压后 150 MB；沿用完整校验、失败回滚、权限与 CSRF。文章不支持页面布局，导入也不会绕过此约束。不包含第三方 CMS 或 Markdown 迁移。

## 评论互动

评论列表显示所属内容、编辑入口和已发布页面入口。支持按称呼或评论正文搜索、点击「只看此内容」、分页选择和批量通过、隐藏、删除；批量操作先验证全部记录，部分记录已删除时不执行剩余项。

管理员可以填写一条官方回复，并编辑或清空；管理员和编辑都可以审核评论。回复为纯文本，评论通过审核后才一起公开。未审核评论的回复不会提前公开；没有增加访客注册或楼中楼讨论。

## 管理员应急恢复

只有拥有服务器终端权限的维护人员可以执行。先停止原 API，使用原数据库、附件和密钥配置；不通过网页暴露恢复接口，也不把密码放进命令参数或配置。

已部署的 Docker 站点在原部署目录执行（用户名替换为现有管理员）：

```sh
docker compose -f compose.yaml stop api
docker compose -f compose.yaml run --rm --no-deps api --reset-admin=你的管理员账号
docker compose -f compose.yaml up -d api
```

宿主机 Nginx 模式沿用原来的 `-f compose.host-nginx.yaml` 参数。直接运行已发布程序时，在相同环境配置下执行 `dotnet Cms.Api.dll --reset-admin=账号`。

命令要求两次输入 12–200 字符的新密码，交互输入不回显，完成后退出；脚本可通过标准输入传入两行密码，应避免写入日志或文件。两次不一致、非管理员或账号不存在时拒绝修改。重置会启用该管理员、使旧会话失效并撤销其所有 API 访问令牌，须按需重新签发令牌。审计只记录操作对象，不记录密码。该命令不能与初始化、迁移或备份恢复同时使用；重新执行 `--initialize` 仍不会重置密码。

## 通知测试与负责人邮箱

「通知记录」提供发送测试邮件、发送企业微信测试。测试进入原有持久队列，下方自动刷新排队和发送结果，最多约一个调度周期开始发送；每个渠道每分钟最多创建一条测试通知。失败沿用自动重试及手动重新排队，成功记录不能再次重试。

测试只发到部署配置中的站点收件人或企业微信群，不接受前端传入任意收件地址或消息正文。显示「已发送」表示接收服务接受了请求，仍应核对邮箱或群中是否收到。测试接口仅管理员可用并要求 CSRF。

成员可设置通知邮箱。新咨询及逾期咨询的邮件在发送时读取当前负责人：负责人启用、具备管理员或咨询专员角色且有邮箱时发给该负责人，否则使用站点固定收件人。企业微信仍发往配置的运营群。消息只包含事件与后台链接，不包含客户联系方式。配置和正式投递要求见 [通知说明](next-enhancements.md#主动通知配置)。

## 操作记录筛选

可按操作者、操作类型、对象名称或标识、开始与结束时间筛选；输入时间使用浏览器本地时区，发送和存储使用 UTC。新增操作类型均有中文名称。显示操作者姓名，同时保留原标识；兼容早期纯账号标识及已有「姓名（标识）」格式，姓名快照保留当时名称。

## 咨询专员与我的待办

管理员创建成员时可选择「咨询专员」。其后台首页为自己的咨询，只能读取、跟进、导出分配给自己的记录及跟进历史，不能转派、删除、访问访客轨迹或整站管理功能。列表、详情、导出和更新均在服务层校验当前账号和负责人；伪造负责人筛选也不能越权。

管理员可以分配给启用的管理员或咨询专员，并查看全部咨询；「我的待办」仅显示自己负责且未完成、未作废的记录，取消勾选后恢复全部可见范围。编辑仍负责内容，不获得咨询权限。咨询专员不能创建内容访问令牌，也不能凭登录状态读取未公开附件。角色变更沿用旧会话失效机制。
