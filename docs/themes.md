# 主题使用说明

管理员进入后台 **主题外观**（`/admin/themes`）。默认保持经典博客；编辑角色不能管理主题或访问主题预览。

## 选择与应用

1. 页面自动选中当前启用的主题。在左侧列表选择其他主题，可按名称或风格搜索；右侧展示大图和设置，点击图片可在新标签页查看原图。手机和平板采用上下布局。图片来自实际首页的示例内容，自己的文章和自定义效果请使用“预览主题”查看。
2. 编辑主色、首页标题和首页介绍。标题最多 100 字，介绍最多 500 字；只接受纯文本。主色使用 `#` 开头的六位十六进制颜色，也可用颜色选择器。系统自动搭配可读的按钮文字和链接颜色。
3. 点击“预览主题”，在新标签页查看当前表单效果。此时访客仍看到原主题。
4. 点击“保存并启用”切换主题；编辑当前启用主题时显示“保存并应用”。设置与启用在一次事务中保存，并产生主题操作记录。

每套主题独立保存自己的设置。切换回来配置时，会载入它上次保存的主色、标题和介绍。标题留空使用该主题默认标题；介绍留空使用站点介绍。站点名称、Logo、菜单、浏览器标题和 SEO 继续由站点设置及内容摘要决定。

“恢复默认”只重置当前表单，保存前不会影响网站。切换编辑对象、离开页面时有未保存提示；保存失败保留输入。若出现其他管理员已修改的冲突提示，先复制需要保留的输入，再点击“重新加载”，按最新配置重新编辑并保存。

## 十五套内置主题

- **经典博客 `classic`**：浅色蓝色设计，首页介绍和图文卡片，保留原有布局。
- **极简阅读 `paper`**：暖白底、窄版单列目录，隐藏列表封面占位，强调正文阅读；文章详情仍可显示封面。
- **杂志资讯 `magazine`**：首页第一页突出最新文章，其他文章使用多列图文；后续分页使用普通列表。
- **暗色科技 `midnight`**：深色背景、青色强调和紧凑卡片，深色代码块适合技术内容。
- **Fuwari · 清新卡片 `fuwari`**：圆角卡片、分类标签侧栏、右侧文章封面；无封面时自然使用整行文字，手机上侧栏移到正文之后。采用无横幅布局。
- **Retypeset · 重新编排 `retypeset`**：桌面左侧站点导航、右侧文字文章列表，使用系统衬线字体，适合长文阅读；手机上导航回到顶部。
- **Cactus · 极简技术 `cactus`**：深色等宽排版、紧凑的日期与标题列表、绿色强调，适合技术记录。
- **Chirpy · 技术手记 `chirpy`**：桌面左侧导航、横向文章卡片、右侧资料栏与正文目录；手机上封面移到卡片顶部。
- **Oranges · 橘子日记 `oranges`**：居中页头、暖色点缀、日期与标题目录，无封面占位，适合轻量文字博客。
- **Aircloud · 云间文字 `aircloud`**：轻盈左侧导航、时间与标题行、真实标签链接；手机上按日期和标题上下排列。
- **Stellar · 星光笔记 `stellar`**：柔和导航栏、大圆角卡片、封面和阅读空间；当前提供博客版，不含完整知识库。
- **Halorum · 话题列表 `halorum`**：采用原作 Typecho Theme JJ 的紧凑信息流，展示分类、日期、标题和摘要；当前是文章列表版，不提供论坛账号、通知、投稿或虚构统计。
- **Aurora · 极光图文 `aurora`**：渐变介绍、首页首篇头条、图文列表及个人侧栏；第二页起使用普通列表。
- **iEmo · 温柔日常 `iemo`**：温暖留白、左图右文和个人资料栏，无封面时使用完整文字卡片；手机上封面移到上方。
- **Clarity · 清晰视界 `clarity`**：采用 blog-v3 的左侧导航、中间正文、右侧资料三栏布局；较窄屏幕将资料栏移到正文后。

十一套社区主题的文章和独立页面提供可折叠的二、三级标题目录。目录在浏览器加载后出现，正文始终由服务端直接输出；没有有效标题时隐藏目录。目录链接支持键盘操作及直接定位。

十一套社区主题从各自 MIT / BSD-3-Clause 原作适配为本项目的 React 页面。后台列表和前台页脚不显示原作链接；来源、固定版本和完整许可保留在源码及发布包中，详见 [第三方主题声明](../THIRD_PARTY_NOTICES.md)。它们沿用相同的三项设置，不包含原作全部小部件或动画，也未携带上游字体、头像、演示文章。

主题作用于首页、文章、独立页面、分类标签、搜索、分页和评论区域，管理后台保持统一浅色风格。表格和长代码允许在自身区域横向滚动，避免撑宽手机页面。

## 预览说明

预览地址为 `/admin/themes/preview/[[...path]]`。服务端读取当前 Cookie 会话后交给 API 校验管理员权限；预览只读取已发布内容，不能用来查看草稿。导航、分类标签、搜索和分页保留正在编辑的预览配置，评论只能查看，不能提交。

预览不写入数据库，不生成操作日志，不改变当前主题；页面显示预览提示并设置 `noindex, nofollow`，不会写入 sitemap。地址包含当前外观表单的纯文本参数，但没有账号凭据；其他人即使获得地址也必须具有当前站点管理员身份才能打开。

公开页面服务端实时读取已启用配置，不通过客户端首次换肤。访客下次访问或刷新页面时看到新外观；已打开的旧页面不会自动推送刷新。

## 访客显示模式

十五套主题的前台导航区都有“显示模式”SVG 图标按钮：太阳表示明亮模式、月亮表示黑暗模式、显示器表示跟随系统。点击按“明亮 → 黑暗 → 跟随系统 → 明亮”循环切换，默认跟随系统；悬停提示和无障碍名称说明当前模式及下一模式，键盘 Enter / 空格也可切换。系统模式会立即响应操作系统或浏览器的明暗偏好变化；手动选定的明亮、黑暗模式不会被系统覆盖。

选择只保存在当前浏览器的 `cms-color-mode` 偏好 Cookie 中（有效期一年），不会修改管理员设置的站点主题或其他访客的外观。刷新、新标签页、返回页面时保留选择，切换不会清空正在输入的评论。主题预览也支持此按钮，后台管理界面继续使用原有浅色配色。

页面首次响应已包含显示偏好与两套配色，使用浏览器原生 [light-dark()](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value/light-dark) 和 `color-scheme`，不依赖脚本加载后再切换正文颜色；关闭 JavaScript 时仍能按系统或已保存的偏好阅读，图标按钮不可用。服务端读取偏好使用 [Next.js cookies](https://nextjs.org/docs/app/api-reference/functions/cookies)。运行环境为支持该 CSS 特性的现代浏览器。

模式调整站点及正文默认配色；文章图片、第三方嵌入页面和作者明确指定的富文本颜色保留原样。无数据库升级或后端配置变更；已有十五主题版本只需更新 web 镜像。

## 部署与扩展边界

主题状态表自 schema 3 引入；旧站点先备份并按 [部署说明](deployment.md) 升级到当前版本。新增主题不变更数据库结构，当前 schema 6 无需再次迁移，只需更新 API 和 web 并重启。数据库保存主题配置，主题代码和十五张缩略图随 web 镜像发布；无需更改 Consul 或数据库连接配置。更新本身不会切换已有主题。此前导出的七主题 Docker 包不会自动更新，需要重新构建镜像或导出新包。

API 与 web 需要同时更新到包含这些主题的版本。如需回退到仅含七套主题的旧镜像，先在后台切回经典博客等旧版本支持的主题，再回退镜像。

本期支持以上十五套内置主题。不支持自定义 HTML、CSS、脚本、模板路径、第三方主题上传、主题市场或页面搭建器，也不兼容 Halo 模板。需要增加内置主题时，通过源码更新固定目录、样式和截图并重新发布镜像。

缩略图再生成仅对独立验收站点执行：先构建镜像，设置环境变量 `CMS_CAPTURE_THEME_THUMBNAILS=1` 后运行 `python tests/docker_smoke.py`，截图写入 `web/public/themes/`；然后移除该变量、重新构建 web 镜像并再跑普通验收，确认图片已随镜像发布。不要把验收脚本指向日常站点。

历史四套主题验证见 [主题验收记录](themes-verification.md)，第一批三套见 [社区主题验收记录](community-themes-verification.md)，第二批八套见 [第二批主题验收](theme-batch2-verification.md)。
