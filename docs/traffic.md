# 访问统计与客户咨询

## 使用入口

- 前台文章与独立页面显示累计阅读次数；页面实际显示并成功记录后更新本次阅读数。
- 前台底部提供“咨询 / 预约演示”。称呼、联系方式、需求描述必填，公司或学校选填；提交前需同意联系用途。
- 后台概览增加今日浏览量、今日独立访客和新增咨询。
- 管理员可进入 **访问统计**、**访客记录**、**客户咨询**。编辑仍可查看文章列表中的累计浏览、今日浏览、独立访客，并按浏览量排序；不能访问访客轨迹或客户联系方式。
- 客户咨询可按状态或称呼、联系方式、单位搜索，查看来源页面和浏览器轨迹，记录跟进备注，设置“待联系 / 跟进中 / 已完成 / 无效”。跟进有版本冲突保护和未保存提示；删除咨询会删除该条联系方式及需求。
- 访客列表显示最近一次有效访问的 IP 和所属地区；访问轨迹保留每次访问当时的 IP、地区，换网络不会改写历史。IPv4、IPv6 均支持，地区是 IP 的大致归属地，不代表实时定位。旧记录显示“未记录”。配置、升级与验证见 [访客 IP 与地区](visitor-location.md)。

## 统计口径

- **浏览量（PV）**：浏览器实际显示一次有效公开页面后记录一次。文章、独立页面、首页、搜索、分类和标签列表纳入全站 PV；热门内容仅统计文章与独立页面。
- **重复与重访**：一次页面生命周期使用固定请求编号；网络重试和 React 开发模式重复挂载不增加次数。刷新、重新进入和分页导航是新的浏览；仅滚动或点击正文锚点不增加 PV。
- **独立访客（UV）**：按服务端签发的随机浏览器标识，在选定统计区间内去重。跨天汇总重新去重，不把每日 UV 相加。不同设备、清除或拒绝 Cookie 都可能使同一人重复计数，不能用于确认实名身份。
- **日期**：统一使用北京时间（Asia/Shanghai），显示最近 7 天、30 天或不超过 90 天的自定义日期范围。数据库时间保存为 UTC。
- **来源**：优先记录链接上的 `utm_source` 和 `utm_campaign`，否则只保存外部来源的主机名。站内来源显示“站内”，来源缺失显示“直接 / 未知”。不保存完整来源网址或搜索参数。来源排行最多显示 100 项。
- **设备**：根据浏览器声明粗分电脑、手机、平板，不构建设备指纹，也不据此判断真实身份。
- **阅读时长**：累加页面可见时间，约每 15 秒及离开页面时上报；后台标签页不累计。服务端按经过时间校验，上限为单次四小时。关闭、断网、脚本屏蔽可能造成少量漏报。
- **阅读深度**：文章正文已进入视窗的最大比例，0–100%；可见时长与深度均属于近似阅读行为，不证明用户已理解内容。重复或乱序上报不会累计放大数值，也不会覆盖较大的历史值。
- **下载**：记录公开附件链接的点击，不代表文件传输完成。自动加载图片和音视频不算下载点击。
- **咨询**：咨询入口点击与成功提交咨询分开统计。重复提交同一请求编号只创建一条咨询；已删除咨询不再纳入咨询数量和每日咨询图表。

SSR 页面生成、SEO 元数据查询、链接预加载、草稿与主题预览、已登录工作人员访问以及已识别爬虫不计入访问。爬虫识别和限流不能保证排除所有伪造流量。未执行浏览器脚本的访问不记录；没有历史数据时显示零，不填充模拟数据。

## 隐私与权限

- `cms.visitor` 使用经过签名保护的随机值，HttpOnly，生产环境 Secure，有效期 180 天；UV 仍按该标识去重。有效访问保存服务端通过可信代理获取的 IP 和本地解析的地区，仅管理员可读，不保存原始 User-Agent，不向第三方发送 IP。
- 浏览器设置 `Do Not Track = 1` 时，前台停止访问和阅读行为采集，咨询表单仍可使用。提交咨询所需的去重身份与联系方式仅用于咨询处理。
- 公开咨询接口只返回请求编号，不返回联系方式或咨询内容。公开文章和评论也不返回客户信息。
- 全部写接口沿用现有 CSRF 校验；访问与咨询分别按可信代理解析后的 IP 限流，访问另有限制单一浏览器的高频打开，咨询另有限制每个浏览器一小时内的提交数。
- 跟进和删除由管理员执行，操作日志只写咨询编号及通用对象名称，不复制联系方式、需求或备注。读取访客、统计和客户接口也要求管理员角色。
- 默认不自动清理访问明细；schema 9 可配置保留期限，仍保留累计浏览量和累计访客数，详见 [维护策略](editorial-enhancements.md#备份与明细维护)。Cookie 到期不会删除统计，客户咨询可在后台逐条删除。

## 数据库升级与部署

访问统计从 **schema 7** 引入；当前版本为 **schema 10**，新增 [页面搭建与首页选择](page-builder.md)。6 → 7 新增访客、访问明细、阅读计数、点击和咨询表；7 → 8 增加 IP / 地区，旧行留空。8 → 9 增加咨询负责人、联系计划、逐次跟进、独立访客累计记录及维护状态，同时完善内容历史和发布管理。累计阅读计数独立于文章版本和公开快照，保存、重新发布、清理旧明细不会覆盖次数。

部署前停止旧 API、前端并备份数据库，更新两个镜像后按原 Compose 参数启动。API 在接收请求前自动升级数据库，无需额外的升级界面或手动命令。需要单独执行升级时仍可使用：

```sh
docker compose run --rm --no-deps api --migrate
```

宿主机 Nginx 部署继续使用原有 Compose 文件参数。升级失败时 API 停止启动，修复原因后可重试；重复迁移或重启不会重置已有访问或咨询。首次安装仍需初始化，升级不会重设管理员。回滚旧程序应同时恢复对应的旧数据库备份。

继续采用现有单 API 实例、Repository/FreeSql 分层及事务写入机制。IP 地区使用内置离线库及 IP2Region.Net 3.0.2，不增加在线服务依赖；可通过 `GeoIp:Directory` 替换地址库。统计从功能启用后开始；如需恢复历史量，须另行分析保存完好的访问日志，不能直接凭空回填。

## 验证入口

```powershell
dotnet build Cms.slnx -c Release --no-restore
python tests/traffic_acceptance.py all
npm --prefix web run api:types
npm --prefix web run typecheck
```

`traffic_acceptance.py` 为每次运行创建隔离数据库，验证 6 → 7 升级、重复升级、并发去重、PV/UV、阅读记录、权限、咨询跟进与重启持久化；支持 SQLite、PostgreSQL、MySQL、SQL Server。

浏览器流程在 `web/tests/traffic.spec.ts`，使用显式指定的隔离 HTTPS 测试站点运行，覆盖实际导航、阅读、下载、咨询、跟进、预览排除、DNT、Cookie 属性和 375 / 768 / 1440 像素布局。可通过现有 `tests/docker_smoke.py` 连同其他前后台流程执行。实际执行结果见 [验收记录](traffic-verification.md)。
