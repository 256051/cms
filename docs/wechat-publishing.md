# CMS 接入微信公众号

可以接入。当前版本已实现「CMS 网站发布 → 同步公众号草稿箱 → 人工处理或可选自动发布」。同步和自动发布均默认关闭，尚未连接真实公众号；不保存微信文章 URL。

## 先区分三个动作

| 动作 | 结果 | 本次范围 |
| --- | --- | --- |
| 同步草稿 | 文章进入公众号草稿箱 | 已实现，可手动或随网站发布自动同步 |
| 公众号发布 | 提交发布任务，查询并保存最终状态，不保存微信文章链接 | 已实现，默认关闭，需要账号具备发布接口权限 |
| 群发给粉丝 | 提交群发任务，核对结果和实际发送人数 | 后续阶段，需要单独的群发权限、额度和接收范围 |

不能把 `draft/add` 返回的 `media_id` 当作已发布文章，也不能把发布接口返回成功当作粉丝已收到消息。微信当前发布文档对账号类型有权限限制，最终以该公众号「开发接口管理」里可用权限为准。[新增草稿](https://developers.weixin.qq.com/doc/service/api/draftbox/draftmanage/api_draft_add.html)、[发布草稿](https://developers.weixin.qq.com/doc/service/api/public/api_freepublish_submit.html)、[群发消息](https://developers.weixin.qq.com/doc/service/api/notify/message/api_masssend.html)。

## 实现步骤与进度

1. **核实账号权限。** 准备目标公众号 AppID、AppSecret；确认素材、草稿接口权限，将 API 服务器的公网出口 IP 加入白名单。第一版一个站点绑定一个自有公众号，第三方平台授权、多账号未接入。
2. **配置公众号凭据。** 管理员在「系统管理 → 公众号设置」填写账号，保存到数据库；复用 ASP.NET Core Data Protection 加密，密钥不回显，保存无需重启。Consul／环境变量仅作为可选的部署覆盖；使用 stable token 普通模式及有效期缓存，不强制刷新其他系统的凭据。
3. **转换发布快照。** 使用已经在网站发布的标题、摘要、正文、封面和原文链接；上传永久封面素材，正文图通过微信图文图片接口上传并替换 URL。同篇正文重复图片只上传一次，原 CMS 正文保持不变。
4. **提交独立同步任务。** 编辑页「发布设置」可勾选本次发布是否同步；未勾选不发送，未配置接入时置灰。定时发布及未指定选择的集成 API 沿用有效配置默认值。需要同步时在网站发布事务内保存快照任务，再由独立后台服务每 30 秒处理最多 10 条草稿及 10 条就绪发布／查询任务。事务中不调用微信，微信网络故障不回滚已经成功的网站发布。
5. **显示结果并处理重复操作。** 编辑页增加「微信公众号」区域、手动同步、状态刷新和明确失败重试。按公众号、文章、实际同步内容指纹去重；原样再发布或重复点击复用记录。不同内容版本会创建独立草稿，不覆盖运营人员已经在微信后台修改的草稿。
6. **补齐异常与恢复。** 校验失败、权限不足、额度不足记录可读原因；待发送文章已下架或删除时取消。请求已提交但超时、进程中断或响应缺失时保留「结果待核实」，不会自动创建第二份草稿。备份包含记录，恢复后未确认任务不会自动重发。
7. **分阶段联调。** 先手动同步一篇短图文，核对图片、排版、原文链接，再按需要开启自动同步和自动发布。自动发布会查询微信最终状态，提交成功不会显示为已发布；群发仍是后续阶段。

## 后台配置（默认方式）

1. 管理员进入 `/admin/wechat`，即「系统管理 → 公众号设置」。
2. 填写公众号 AppID、AppSecret、默认作者和网站 HTTPS 根地址。地址应为 `https://example.com`，不要填写 `[https://example.com](https://example.com)` 这类 Markdown 链接。
3. 勾选「启用公众号同步」并保存。保存到数据库后立即生效，无需修改服务器文件或重启。
4. 打开文章编辑页，勾选同步；已经打开的文章页面可点「重新检查接入」或刷新。

AppSecret 加密保存，后台读取时只返回“已保存”标识。再次编辑时留空保留同一 AppID 的密钥；更换 AppID 时必须重新填写对应的密钥。普通编辑只能读取同步就绪状态，不能查看或修改接入配置。配置支持版本校验，避免多人编辑时覆盖。

数据库记录位于独立表 `cms_wechat_settings`，账号配置整体加密保存在 `ProtectedJson`。备份包含该表，恢复时必须配套保留原站点的 `Security:KeyPath` 密钥目录；单独复制数据库到另一套密钥下不能解密。

「定时发布和 API 发布默认同步」可先关闭。编辑页本次勾选始终优先，保存设置本身不会向微信发送内容，也不代表已验证真实接口权限和 IP 白名单。

「同步草稿后自动发布」默认关闭。打开后只在**新建同步任务**时保存自动发布意图，不会扫描补发已有草稿；手动同步、编辑页勾选同步、定时及 API 自动同步均使用该规则。关闭后尚未提交微信的任务会取消自动发布，但已获得 `publish_id` 的任务仍继续查询。只关闭 `AutoSync` 不会取消已经入队的任务；关闭整个公众号接入则暂停草稿、发布和状态查询，重新开启后继续处理。文章页会明确显示「草稿箱」或「自动发布」模式。

## Consul／环境变量覆盖（可选）

只有运维需要集中管理或锁定配置时才使用这种方式，不是后台配置的前提。当前顺序为：显式环境变量 → Consul／服务器配置 → 数据库默认值。存在任一 `WeChat` 字段覆盖时，后台提示“由部署配置覆盖”并禁止保存，避免产生保存成功却不生效的误解。新版默认 `appsettings.json` 不再包含空的 `WeChat` 节点值。

如需使用 Consul，在现有 KV 路径（`Consul:Key`，默认 `cms/config`）的 JSON 文档中合并以下 `WeChat` 节点，保留同一文档中的数据库、存储等其他设置：

```json
{
  "WeChat": {
    "Enabled": true,
    "AutoSync": false,
    "AutoPublish": false,
    "AppId": "你的公众号AppID",
    "AppSecret": "你的公众号AppSecret",
    "Author": "作者名称",
    "SiteUrl": "https://你的域名"
  }
}
```

- `Enabled`：开启公众号草稿功能。
- `AutoSync`：定时发布和未传 `syncToWeChat` 的 API 发布默认值，建议先为 `false`。编辑页「保存并发布」以本次勾选为准：默认不勾选，显式取消会覆盖全局自动同步配置。不补发存量文章。
- `AutoPublish`：新同步任务创建草稿后自动提交发布，默认 `false`。需确认账号有发布接口权限；发布成功也不会群发给粉丝。
- `SiteUrl`：公开网站 HTTPS 根地址，不含路径、查询参数或片段，用于「阅读原文」。
- API 部署需设置 `Consul__Enabled=true`、`Consul__Address=http://你的Consul地址:8500`、`Consul__Key=cms/config`，启用 ACL 时另设 `Consul__Token`。现有 `Configuration.AddConsulAsync` 在启动时读取该 KV JSON，Consul 覆盖变更后需重启 API；数据库后台保存则无需重启。
- 环境变量对应 `WeChat__Enabled`、`WeChat__AutoSync`、`WeChat__AutoPublish`、`WeChat__AppId`、`WeChat__AppSecret`、`WeChat__Author`、`WeChat__SiteUrl`。显式环境变量优先于 Consul，不要使用空值覆盖已有有效设置。
- 密钥不提交到 Git，也不填到浏览器公开环境变量。Consul KV 中的密钥是运维配置，须使用服务已有的访问控制。

Docker 用户选择 Consul 时沿用已有 `Consul__*` 配置即可。如果使用环境变量，须实际加入 API 服务的 `environment`；只在 `.env` 中增加未被 Compose 引用的变量不会注入容器。例如合并以下片段到部署用的覆盖文件：

```yaml
services:
  api:
    environment:
      WeChat__Enabled: "true"
      WeChat__AutoSync: "false"
      WeChat__AutoPublish: "false"
      WeChat__AppId: ${WECHAT_APP_ID:?设置公众号AppID}
      WeChat__AppSecret: ${WECHAT_APP_SECRET:?设置公众号AppSecret}
      WeChat__Author: ${WECHAT_AUTHOR:-}
      WeChat__SiteUrl: ${SITE_URL:?设置公开网站HTTPS地址}
```

在原部署启动命令中附加这个覆盖文件，保留原 Compose 项目名、数据卷及端口。使用 Consul 时不要额外注入相同的空环境变量，以免覆盖 Consul 值。

从前一版部署配置切换到数据库时，先移除已有 `WeChat` 文件配置、Consul 节点及 `WeChat__*` 环境变量并重启 API，再在后台填写并保存。不会自动将部署密钥复制到数据库。

## 编辑人员操作

1. 上传 JPG/PNG 封面和正文图。在「发布设置」勾选「同步到微信公众号（草稿箱）」，点击「保存并发布」；默认未勾选时只发布网站。
2. 未启用、配置不完整、配置加载失败或正在加载时，勾选项不可用并说明原因；后端也会拒绝未配置却要求同步的发布请求。已发布文章也可在「微信公众号」点击「同步已发布版本」，再查看同步结果。
3. 仅同步草稿模式下，看到「已同步草稿」后打开微信公众平台核对、预览并手动发布。自动发布模式下，等待「微信已发布」；处理中不要同时到微信后台手动发布同一草稿。
4. 勾选仅控制本次「保存并发布」，不会保存为文章的永久偏好，也不改变定时发布配置。保存草稿、修改尚未发布的正文不会同步；定时发布按 `AutoSync` 执行。

发布 API 可传 `{"version": 版本号, "syncToWeChat": true}`；`true` 要求配置就绪并同步，`false` 明确不发送，省略或 `null` 沿用 `AutoSync`。管理员和集成发布使用相同规则；勾选状态不需要增加数据库字段。

状态含义：

| 状态 | 应做操作 |
| --- | --- |
| 等待同步／正在上传图片／正在提交草稿 | 等待后台任务并刷新 |
| 已同步草稿 | 表示接口确认创建过草稿，仍需在微信后台检查；不是粉丝推送成功 |
| 同步失败 | 修正权限、网络或素材问题后重试该版本；正文内容问题需修改并重新发布，生成新版本 |
| 结果待核实 | 在公众号草稿箱按标题和时间查找并人工处理；此版本不会自动重发 |
| 已取消 | 发送前发现网站文章下架或删除；需要人工处理后续同步 |
| 等待自动发布／正在提交发布／微信发布中 | 等待处理或查询，不能当作已发布 |
| 微信已发布 | 微信查询确认成功，不表示群发成功 |
| 微信发布失败 | 根据错误处理；明确未受理的提交可「重试发布」，复用已有草稿；已受理后审核失败需到微信后台处理 |
| 发布结果待核实 | 提交超时、编号缺失或提交时中断，禁止自动重发，需到微信后台核实 |
| 自动发布已取消 | 开关关闭或网站下架阻止了尚未提交的发布；草稿可能仍保留在微信后台 |

同步记录是提交历史，不实时反映微信后台的后续编辑、删除或群发。自动发布只跟踪至终态，不持续监控发布后的删除或封禁；人工发布后不回填链接或发布状态。网站下架不会删除微信端已创建的草稿或文章，也无法撤回微信已受理的发布任务。

## 第一版边界

- 仅同步普通文章 `post` 的已发布快照；页面、模板、产品、案例不自动发送。
- 标题最多 32 字、作者最多 16 字、摘要最多 120 字。超限提示修正，不静默截断；目前没有独立的公众号标题字段。[草稿字段说明](https://developers.weixin.qq.com/doc/service/api/draftbox/draftmanage/api_draft_add.html)
- 第一版封面仅接受小于 10 MB 的 JPG/PNG；正文图片仅接受小于 1 MB 的 JPG/PNG。WebP、GIF 等请先转换，本次未增加图像转换依赖。[永久素材](https://developers.weixin.qq.com/doc/service/api/material/permanent/api_addmaterial.html)、[正文图片](https://developers.weixin.qq.com/doc/service/api/material/permanent/api_uploadimage.html)
- 第一版不转换音视频和嵌入网页，遇到这些内容会明确报错。网站主题样式不会完整搬到微信，需在公众号后台预览。
- 同步内容变化会新建草稿；未实现自动更新、删除微信草稿、跨任务素材缓存和批量补发。
- 明确失败由编辑手动重试；未配置自动退避重试。提交结果未知不能直接重试，因为草稿新增接口没有本实现可依赖的幂等凭据。
- schema 16 → 17 新增同步记录表 `cms_wechat_drafts`，17 → 18 新增加密配置表 `cms_wechat_settings`，18 → 19 新增发布任务表 `cms_wechat_publications`；不修改现有业务表结构，不新增 NuGet 包。沿用单 API 实例边界，不适用于多个 API 副本并发处理任务。
- 任务入队与网站发布在同一数据库事务中，数据库写入失败时整个发布回滚；微信接口失败仅影响后续同步任务。

## 自动发布与后续群发

**自动发布文章（已实现）：** 先核实权限，使用成功的草稿 `media_id` 调用 `freepublish/submit`；持久化 `publish_id` 后显示「微信发布中」，后台通过 `freepublish/get` 轮询，只有 `publish_status=0` 才显示成功。保存状态和失败原因，不保存 `article_id` 或文章 URL。查询暂时失败会继续查询原任务，不重新提交；提交超时、编号缺失或提交中断按未知状态处理，不能无条件重发。备份恢复后只继续查询已有任务编号，其余未完成记录进入待核实。尚未接入事件回调。[查询发布状态](https://developers.weixin.qq.com/doc/service/api/public/api_freepublish_get.html)

**群发给粉丝：** 作为独立操作设置接收范围，发送前校验当期额度、预览内容并确认。使用草稿群发能力，持久化微信消息编号及稳定的请求去重编号，通过状态查询／验签解密后的事件核对结果和发送人数。不应先自由发布再假设该草稿仍可群发；草稿在发布或群发后会从草稿箱移除。最终发送还可能受原创校验、平台审核和管理员确认影响。[群发说明](https://developers.weixin.qq.com/doc/service/api/notify/message/api_masssend.html)

群发当前没有开放按钮或后台自动操作。待确认公众号类型、接口权限和接收范围后，再接入群发能力。

## 验证

### 同步失败排查

后台记录会显示具体失败步骤，例如「获取微信访问凭据：DNS 解析失败」「上传微信封面：微信接口返回 HTTP 502」或「读取封面文件失败」。旧版本的「素材准备或网络请求失败」只表示创建草稿前遇到未分类异常，不能据此判断是白名单、密钥还是网络问题；旧记录不会自动补出细节，更新后需重试明确失败的任务。

在服务器原部署目录沿用现有 Compose 参数执行 `docker compose logs --since 10m api`，查找 `WeChat operation failed` 或 `WeChat worker failed`。日志通过 `JobId`、`ContentId`、`AssetId` 和 `Step` 定位，不输出密钥、请求查询串或原始响应。web 容器不带参数访问 `stable_token` 返回 `41002 appid missing`，只能证明该容器到微信接口连通，不能替代 API 容器上传流程验证。

### 本地检查

```powershell
dotnet build Cms.slnx -c Release --no-restore
dotnet run --project tests/Cms.Checks --no-restore -- --wechat
npm --prefix web run typecheck
python tests/wechat_browser.py
```

服务检查使用临时 SQLite 数据库及模拟微信 HTTP 响应；覆盖配置加密、密钥留空保留、版本冲突、部署覆盖、发布快照隔离、图片替换、去重、凭据缓存、明确失败重试、超时不重发、定时发布、可选自动发布、状态查询、权限及审核失败、重启继续查询、关闭开关、下架取消、升级及备份恢复。浏览器检查使用隔离站点验证后台配置保存、不回显密钥、管理员权限、文章同步勾选就绪状态、认证、CSRF，以及模拟的发布状态展示和桌面／手机布局。

真实公众号的权限、白名单、实际图片接收、微信最终排版及群发均需配置账号后联调；本地模拟通过不代表已完成线上推送。
